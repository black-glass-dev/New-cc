# ADR0041 — Explicit experimental graded export, not automatic guard removal

Session date2026-10-18. Supersedes candidate being test-source-only; shipping grade guard stays.

The original surface decoder exists and is connected to guarded candidate configuration.
A user cannot validate it if only an instrumentation entry exists. Offer a separate, explicit
consented experimental path from the shipping active-grade failure Details dialog, only for
Gallery destination, active grades and Android29+. It is NOT automatic retry/fallback.

A second bilingual confirmation discloses720p H.264/AAC SDR test preset, unverified GPU/device
correctness, no4K/10bit claim, strict codec/color/geometry failure and no ungraded substitute.
Only affirmative consent chooses ExportRoute.EXPERIMENTAL_GRADED; default remains SHIPPING.
Capture a fresh immutable clip list after consent, use candidate timing validation, retain
separate gap-compaction consent and existing worker cancellation/cleanup/Gallery publication.
Candidate writes real Transformer output; output container/duration checks precede Gallery.
They are not pixel/parity validation. Current saved grades are exported, not unsaved UI draft.

Candidate encoder fallback is OFF: unsupported encoder configuration fails rather than
silently modifying dimensions. Plain shipping preset keeps previous behavior. No silent
source color interpretation, HDR mapping, proxy substitution, or downgrade to ungraded export.
Runtime operation context reports route. Native validation before every rendered release
remains. Pure route policy tests cover API26..40, active/no active grade and unsupported SDK.

This makes a phone-test route reachable, not proven production graded-export support. Real
backend drain, GPU/pixel parity, cut/audio/timing and Gallery/lifecycle acceptance remain.
Only a CI-built candidate may be handed off; no stable signing/update continuity claim.
No external code/assets/dependency; own UI and transport, native domain unchanged.25%/75%.
